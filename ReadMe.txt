LOCAL AI APPLICATION CREATION AND HANDS-ON SETUP
================================================
Project:
commerce-ai-assistant

Purpose:
This project is a hands-on Spring Boot AI application created to learn and implement Generative AI and Agentic AI concepts.

The application will gradually evolve to demonstrate:
- LLM integration
- Prompt engineering
- Claude API integration
- Spring AI
- Structured output
- RAG
- Embeddings
- Vector database
- Tool calling
- MCP
- Agentic AI workflow
- Integration with external/business APIs
- Docker containerization
- Runtime configuration
- Enterprise-style secret management


1. PREREQUISITES
================
Required:
- Windows
- Visual Studio Code
- Git
- GitHub account
- Java JDK 21 or later
- Node.js/npm
- Claude Code CLI
- Internet connectivity

12. SPRING AI / CLAUDE INTEGRATION
==================================
The Spring Boot application uses Spring AI to communicate with an Anthropic Claude model.
Spring AI provides the ChatClient abstraction so that application code does not need to directly construct low-level HTTP requests for every model interaction.

The application uses:
    spring-ai-starter-model-anthropic

Spring AI dependency management should be configured using the Spring AI BOM so that compatible Spring AI modules use consistent versions.


13. AI CONFIGURATION
====================
AI credentials must NOT be hardcoded into source code.
The application should reference environment variables.

Example:
    spring.ai.anthropic.api-key=${ANTHROPIC_API_KEY}
    spring.ai.anthropic.base-url=${ANTHROPIC_BASE_URL:https://api.anthropic.com}

Model configuration should also be externalized.

Example:
    spring.ai.anthropic.chat.options.model=${ANTHROPIC_MODEL}


IMPORTANT:
The actual API key and organization-specific endpoint must never be committed to Git.
Environment variables are used locally during development.
Enterprise deployments should use the organization's approved secret management mechanism.


14. LOCAL AI ENVIRONMENT VARIABLES
==================================
Environment variables can temporarily be supplied to the current PowerShell session.

Example:
    $env:ANTHROPIC_API_KEY="YOUR_API_KEY"
    $env:ANTHROPIC_BASE_URL="YOUR_APPROVED_BASE_URL"
    $env:ANTHROPIC_MODEL="YOUR_APPROVED_MODEL"

Verify only that the variable exists when required.
Do not print or expose the actual secret value.
These values are temporary local-development configuration and should not be committed to Git.


15. AI CONTROLLER
=================
Create:
    src/main/java/com/digital/commerceai/controller/AiController.java

Inject Spring AI's ChatClient.
A basic request can be implemented using:
    chatClient.prompt().user(question).call().content();

The REST API receives the user's question.
The ChatClient sends the request to the configured AI model.
The model generates a response.
The application returns the generated response to the REST caller.

17. AI ORCHESTRATION LAYER
===================================
The application was refactored to separate HTTP handling from AI orchestration.

Responsibilities:

Added:
AiController.java — HTTP/API handling only.
AiService.java — AI orchestration using ChatClient.
AiPromptService.java — centralized system instructions/prompt configuration.

Flow:
REST Request → AiController → AiService → AiPromptService + ChatClient → AI Model → Response

Key change:
Separated REST/controller logic from AI orchestration and prompt configuration.
Added system instructions alongside the user's question.

The application now uses system instructions together with user messages to control the behavior of the AI assistant.

21. RAG SEMANTIC SEARCH WITH LOCAL OLLAMA + REDIS
============================================================
The RAG (Retrieval-Augmented Generation) implementation
using a fully local embedding approach.

The implementation was changed from cloud-based/OpenAI embeddings to a
locally running Ollama embedding model, allowing semantic search to work
without consuming any OpenAI embedding API quota.

This implementation contains the following major areas:

1. Local Ollama Embedding
   - Ollama is installed and running locally on the Windows machine.
   - A local embedding model is used to generate vector embeddings.
   - Spring AI automatically uses the configured EmbeddingModel internally
     during document ingestion and similarity search.
   - No explicit EmbeddingModel object is required in the application
     business code.

2. Redis Vector Store
   - Memurai for Redis is used as the local Redis-compatible server.
   - Redis stores the generated document embeddings and associated document
     information.
   - Spring AI Redis Vector Store is used for semantic similarity search.
   - Docker is not required for the local setup.

3. Knowledge Ingestion
   - Business knowledge documents are created by
     KnowledgeIngestionService.
   - During application startup, the documents are converted into embeddings
     through the configured local Ollama embedding model.
   - The resulting vectors are stored in Redis.

4. Semantic Retrieval
   - RagRetrievalService receives the user's question.
   - The question is converted into an embedding automatically.
   - Redis Vector Store performs similarity search against the stored
     document embeddings.
   - The most relevant documents are returned based on semantic similarity.

5. RAG Context Construction
   - RagContextService converts the retrieved documents into a context
     that can be supplied to the LLM.
   - Only retrieved business information is provided as RAG context.

6. RAG Response Generation
   - RagService defines the RAG-specific system instructions.
   - AiService combines:
       User Question
       + Retrieved Context
       + RAG System Instructions
       and sends them to the configured chat model.
   - The LLM generates the final answer using the retrieved business
     information.

7. REST API
   - The existing AiController was enhanced with the RAG endpoint.
   - No separate controller was introduced for the RAG implementation.

10. Architecture Concept

    The completed implementation demonstrates the complete basic RAG
    lifecycle:

    Business Documents
        -> Local Ollama Embedding Model
        -> Vector Embeddings
        -> Redis Vector Store
        -> Semantic Similarity Search
        -> Retrieved Documents
        -> RAG Context
        -> Chat Model
        -> Final Answer

    The important learning here is that the application code does
    not need to manually create or invoke EmbeddingModel for normal RAG
    processing. Spring AI coordinates the embedding generation internally
    through its configured EmbeddingModel implementation.

11. Local/Free Development Objective

    It stablishes a locally executable RAG environment without
    requiring OpenAI embedding API usage.

    Ollama provides the local embedding capability and Memurai provides the
    local Redis-compatible vector storage required for the hands-on
    implementation.

    This setup is intended for local learning and development. Production
    deployments can later replace the local embedding model and Redis
    infrastructure with enterprise-managed AI and vector infrastructure
    without fundamentally changing the RAG concepts learned here.
